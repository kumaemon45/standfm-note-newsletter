# 長時間音声をMacで文字起こしする

1時間程度の音声など、通常の文字起こしが容量・時間・メモリ制限で失敗した場合に使う。最初にエラー・入力形式・長さ・作業場所・利用可能な文字起こし手段を調べる。25 MBは一部のAPIのファイル上限であり、すべてのアプリや今回のエラーの原因と決めつけない。

## ローカル処理（Apple silicon Mac）

`scripts/transcribe_long_mac.py` はmacOSの `afconvert` と Python の `mlx-whisper` / `numpy` を使い、取得済みの音声または音声付き動画を16kHz・モノラルの一時WAVに変換し、標準10分単位で順番に処理する。各区間は前後3秒を重ね、文字起こしの時間範囲の中心が区間内にある文を採用する。境界は誤認識や欠落の可能性があり、実音声と照合する。話者識別はしない。

- Apple silicon Macと、GPUが利用できる実行環境、Python、依存パッケージ、MLX形式のWhisperモデルが必要。Intel Mac、GPUが利用できない環境、モデルがないオフライン環境で動くと約束しない。初回はモデルのダウンロードと十分な空き容量が必要。必要に応じて専用venvを作り、`python -m pip install mlx-whisper numpy` で準備する。依存導入やモデル取得が環境制限でできなければエラーを伝える。Apple silicon以外は利用可能な別のローカル文字起こし手段を検討する。
- 作業領域内で**録音ごとに独立した**出力先を作る。元音声は変更せず、変換用WAVは出力先の一時フォルダに保存する。処理中は大きなディスク容量が必要。中断時には残りうるため、保存と削除は本人の意向に従う。取得したZoom録画や参加者の発言の利用権限を確認する。
- 例（実際のパスに置き換える。シェルで適切に引用する）：

  ```bash
  /path/to/venv/bin/python /path/to/standfm-note-newsletter/scripts/transcribe_long_mac.py '/path/to/recording.m4a' --output '/path/to/work/recording-01'
  ```

  `--chunk-seconds 600`、`--overlap-seconds 3`、`--model` で変更可能。モデルIDは初回ネットワーク取得が発生しうるため事前に説明する。通常の処理は端末内で行い、音声は文字起こしAPIへ送らない。出力先に `manifest.json`、各 `chunk-0001.json`、完了後 `transcript.txt` ができる。
- 中断後は**同じ入力ファイル・モデル・分割設定・出力先**で同じコマンドを再実行すると、記録された区間を飛ばして続ける。入力内容や設定が異なる場合は処理を中止するため、新しい出力先を選ぶ。原稿が完成していない場合や欠けた区間がある場合は、全文完了と報告しない。元ファイルのアクセス権、変換、モデルロード、GPU、空き容量などの失敗を区別して報告する。
- 完了したら区間数、録音全体の長さ、出力の終端と境界箇所を確認する。無音区間もあるため、文字起こしが空の区間は音声を確認し、無音か認識失敗かを判断する。発話や固有名詞の精度は保証できない。テキストと音声は本人ごとに管理する。

## 別の処理手段

ローカル実行が不可能な場合、利用可能なサービスの入力上限、形式、料金、送信先を確認し、本人に説明してから利用する。大きなファイルは利用するサービスの上限以下に分割し、送信前に各ファイルのサイズを確かめる。処理済み区間と失敗区間を記録し、同様に結合する。Zoomの録画共有URLはログイン・アクセス・ダウンロード権限に依存し、会議参加URLから録画を取得できるとは限らない。
